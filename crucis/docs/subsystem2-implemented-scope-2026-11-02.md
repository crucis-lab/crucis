# Subsystem 2 implementation scope and methodology evidence

Tickets: DLV-08, DLV-09, DLV-10. Local date: 2026-11-02, America/Los_Angeles.
This is an implementation addendum to the accepted design, not an adoption of a
new paper certificate, threshold or public protocol. Final release evidence is
recorded in the implementation log and external bundle receipts. An unfinished
gate is not a pass.

## Authority and source lineage

Uzair approved the final subsystem-2 design and authorized every implementation
bundle in this conversation. The accepted 53-file design baseline is pinned in
`../_w2_checks/2026-11-02_s2_build/accepted-design.json`. Earlier candidate files
retain their historical wording and hashes, including their original pending-go
status. The new log records later acceptance and execution without rewriting that
history. The implementation DAG supplies the bundle ordering and must-show lists.

The new runtime is `audit/experiments/`. It reuses S1's evidence capture, immutable
store primitives, safe legacy codec, native graph checks and explicit compatibility
projection. S1, B5 and shared scientific scoring remain unchanged. Every new S2
observer identifies the actual S2 code manifest; a compiler does not attribute its
work to S1's default implementation identity. Stored bytes, canonical bytes,
record identity, package identity and historical reported hashes remain separate.

## Supported boundary

| Surface | Implemented scope | What it does not establish |
|---|---|---|
| Wire and references | Closed 40-kind SC-2 candidate, 25 exact parameter schemas, 11 typed payload formats; bounded explicit supplied-byte resolution | External retrieval, scientific truth, access authority |
| Profiles | Preservation; installed exact family interpretation; injected exact assessment procedures for stronger profiles | A universal ready flag, native support merely from record shape |
| Case/collection | Source-scoped case revisions, membership occurrences, fixed selection rules and late resolution | Filename equality as case identity, omitted trials as zero population |
| Request/materialization | Task/response/coverage declarations, information constraints, checks on supplied transform evidence | Data generation, encoder fitting, actual transforms or delivery |
| Population/evaluation | Explicit units/dispositions, output/reference/mapping selection and exact external metric descriptors | New metrics, statistical inference, accuracy from a metadata pass |
| Lifecycle | Prior-byte commitments, amendments, event dependencies, permitted-input adaptive decisions and exposure accounts | External preregistration, native action delivery, grants or budget resets |
| Native handoff | Exact scientific/native/response/route registration, S1 request projection and immutable handoff pins | Native bind/invoke/observe, restored state or execution permission |
| Legacy | Captured safe-codec value imports, durable occurrence identity, exact source-backed echo and explicit S1 compatibility views | Original chronology, sample counts, independent repetitions or complete native history from labels |

The A-H examples span global graphs, retrospective partial references, adaptive
interactions, temporal windows, relational/distributed data, learned variables,
weighted native collections and intervention/proxy questions. A family reader
reports exactly the supplied metadata invariant it checks. Missing native support,
unknown epochs, unknown contributors, ambiguous maps, missing particle associations
and unavailable authority retain scoped gaps. Source-account preservation is not
typed scientific support. Composite records retain each applicable family; stronger
claims require every prerequisite rather than a preferred family winning.

The built-in S1 completion rule checks declared response roles/cardinality and
explicit abstention under complete observation coverage. It does not decide causal
correctness. The built-in evaluation descriptor is metadata-only. Scientific S4
metric implementations and S3 execution/authority remain separate owner work.

## Compatibility and recovery details

Request and attempt occurrences are supplied once. Reuse requires identical bound
content; changed intent cannot borrow a previous request identity. Restart/retry
attempts remain S1 attempt history and do not become scientific repetitions. S2
does not automatically create a retry, select a last result or resume a process.

P/M/R/H/O/E are distinct immutable publications, not successive overwrites of one
package ID. Copied records retain identical content. Self-qualified references and
captured typed-payload reference contexts require their actual supplied source
snapshot; publication never silently rewrites those bytes.

Legacy imports consume qualified, explicitly supplied S1 snapshots. They never
traverse RunRecord.files to recover original evidence. Encoded echo preserves its
declared value scope; missing original files remain missing. Battery/item manifests
have separately named codecs and retain n as a source variable-count declaration,
cluster as a source grouping declaration and replicates as recorded occurrences.
None is promoted to observation count, independence or fresh trial population.
Reported cost remains reported and missing cost remains missing. Rich native
objects remain evidence even when a narrow compatibility view cannot express them.

## Evidence interpretation for the paper

The accepted specimen inventory contains 38 packages and 543 S2 records across
all 40 record kinds. Those are synthetic conformance examples, not 38 experiments
or evidence of real causal discovery accuracy. The recorded compatibility checks
use existing captured history. The unchanged auditor recomputes the existing
1,298 comparison values and verifies fresh/stored certificates at its existing
0.001 cross-host tolerance; the new metadata layer does not supply those numbers.

For a methodology claim, cite the accepted rule, the implementation function and
its scoped test/gate together. Retain failed attempts and environment limitations.
Do not infer coverage of an unavailable native system from a schema test, or call
a completed operation a passed scientific assessment. Durable external evidence
archival, W1/W5 paper pointers, ticket repins, public adoption and empirical funded
execution remain owner steps. No tracker, paper or result pointer is changed here.
