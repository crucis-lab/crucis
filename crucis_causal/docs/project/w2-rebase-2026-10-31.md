## 4. How we are going to measure everything we need to
There are three things to measure, and each needs its own instrument.

**4.1 The field (what the audits say about systems).**
- One certified audit per system on its battery.
- One certified **round** per battery: the systems compared on the same items.
- One certified **version comparison** per system pair, the adversary-loop log format (section 5, change V3).
- Every number carries its rule, run set, regime, tier, interval, verdict and label.

**4.2 The auditor itself: does each finding kind catch what it claims?** This is new, and the protocol's credibility rests
on it. A **validation battery of planted faults**: mutant systems built on top of recorded PC outputs and the truth, with
no model calls. Each one has exactly one injected property:

| Mutant | Planted property | Kind that must fire | Kinds that must stay clear |
|---|---|---|---|
| label-reader | returns the graph the shown names imply (truth relabelled by the arm's names map) | K04, K05, K11 | K01, K10 |
| index-orienter | orients every undecided pair from lower to higher column index | K06 on released vs shuffled | K04 |
| link-dropper stage | a second stage deletes a share of true adjacencies | K10 | K12 |
| flipper stage | a second stage reverses a share of correct arrows | K12 | K10 |
| knowledge-overrider | replaces data arrows with a planted wrong order | K07, K09 (oracle vs wrong) | |
| overclaimer | states 0.95 on every edge | K14 | |
| commits-all | orients every adjacency, never abstains | K15 | |
| crasher | fails on a seeded share of items | K01 | |
| null twin of each | the same code with the fault switched off | none of the above | all |

- **Measured:** power (the share of seeded fault strengths at which the kind fires, as a curve over strength) and false
  alarms (fires on a null twin).
- It is free and CPU-only, and it becomes a certified `validation@v1` output.
- **The paper can then say "each finding kind fires on its planted fault at strength >= x and never on its null twin",
  instead of asserting that the kinds work.**

**4.3 The chain from raw run to printed number.**
- Raw run -> certificate: `audit verify`.
- Certificate -> paper: W1's `build_numbers.py --check`.
- Stored audit -> package: the 0.001 table.
- Host -> host: the same certificate verifies on Windows (tolerance 0.001 across hosts).
- Each verdict also gets its **margin** (the distance of the point or interval end from the threshold) and a fragility flag
  (the verdict changes under 5 bootstrap seeds). A reader then sees which verdicts are close calls.

## 6. The paper contract (frozen in package v1.1)
1. **Layout.**
   - `audit/results/rerun_v1/<audit>/{report.json, report.md, certificate.json}`.
   - `<audit>` is the audit name exactly: `matmcd`, `causal_copilot@bnd08`, `pc@semantic`.
   - Rounds are `round@<battery>`; version comparisons are `versions@<system>-<a>-vs-<b>`.
   - No `reports/` level, and no `@` rewriting.
2. **Findings are addressed by `id`, not position or name.**
   - `certificate.json#/body/findings/[id=K04]/effect/point`; `/effect/lo`, `/effect/hi`, `/verdict`, `/label`,
     `/label_rule` sit beside it.
   - Note to W1: the example `[kind=K04]` would not resolve. In the package `id` is `K04` and `kind` is `name_reliance`.
     Both names are frozen.
3. **Certificate findings mirror report findings** (`effect`, `threshold`, `verdict`, `label`, `margin`, `measured_on`,
   `judged_on`, `stage`, `reason`). The same pointer then works in both files, with `/body` in front in the certificate.
4. **The numbers block** becomes `{pointer: {value, unit, source: {file, sha256, pointer}, derivation}}`. The source is the
   audit's `report.json`.
5. **Regeneration rule.** `rerun_v1` is regenerated only by `python -m audit rerun`. The environment block names the host.
   Values are host-independent (checked by verify), so a regeneration on Windows changes the environment fields only;
   the paper's lock will show that as a file change, not a value change.

## 7. W2's notes on W1's section 2 (also written into `claude/q1-checkpoint-2026-10-31.md`)
1. **"Review lowers adjacency F1 0.584 -> 0.321" misattributes the loss.**
   - On fork main, over the 22 completed runs, the drop is almost all in the bootstrap step (S0 -> S1: -0.270
     [-0.327, -0.200]), which makes no model call. The LLM review step itself (S1 -> S2) is +0.007 [-0.027, +0.042]. KCI and
     the cycle step change nothing measurable.
   - BND-08's gpt-4o runs agree: -0.281 at the bootstrap step, -0.003 at review.
   - Suggested wording: "Causal-Copilot's refinement lowers adjacency F1 from 0.584 to 0.321, and the loss is in its
     bootstrap step, not in the model's review."
   - The 0.584 is the S0 mean over 30 runs and 0.321 the final mean over 22 completed runs. The completed-only S0 mean is
     also 0.584, so the mixed run sets do not change the numbers. The package will cite the paired, completed-only form.
   - Program v3 section 2.3 item 3 says "review" too (W5).
2. **The name-reliance sentence pools unlike measurements.**
   - Causal-Copilot's 0.167 is directed F1 on S3 (the graph handed to the cycle step) under the committed-marks rule, by
     families. The agents' numbers are final-graph F1 under the expectation rule, by scenario.
   - The two groups ran on different scenarios (0 of 10 shared).
   - P9 was pre-registered that way, so the claim stands as P9. But the text should say what the Causal-Copilot number
     measures, and that under protocol v1 its K04 is exploratory (runs of 11 Oct, before the 14 Oct pre-registration,
     which declared it "already measured").
3. **MATMCD below its data-only graph.** K07 fires under P10's point rule (confirmatory), with interval [-0.066, 0.001]:
   the upper end touches zero. Print the interval, or call it "below on the point estimate".
4. **81 of 101.** The counts reproduce exactly (K11). K11's own threshold is exploratory; the pre-registered verdict is
   BND-08's M3. Under V4 the certificate carries both.
5. **"8 of 8 cycle-step entries crash."** Reproduced: 8 runs enter the cycle step (cyclic S3 by the pipeline's test), all 8
   crash, 0 complete. The package's counterpart is K01 with its stage, plus the version comparison (V3).
6. **CausalArena and CausalBench stay (DLV-11), agreed.** K06 measures a system's reliance on column order; the FCI gain is
   a property of the scoring rule. The data-shape keys (`s1.*`, `s2.*`, `cb.*`) also stay: `MAPPING.json` is the source of
