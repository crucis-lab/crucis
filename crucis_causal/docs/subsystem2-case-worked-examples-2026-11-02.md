## 1. Example A: a prospective synthetic benchmark

Scientific purpose: examine whether outputs change when only presented variable
names change. A development source specifies three observed variables with
A := U_A, B := 2A + U_B, C := -B + U_C, with independent standard-normal exogenous
variables. The associated generating DAG is A -> B -> C. This is a hypothetical
source specification, not a newly generated dataset or verified implementation.

### Complete account of the planned case

- Identity/revision: a current local definition of the planned evidence situation,
  linked to the source specification revision. No empirical case is counted as
  materialized merely because this identity exists.
- Boundary: one intended realization of 1,000 iid rows over A/B/C, distinguished
  from another realization, another sample-size condition and the source recipe.
- Evidence bindings: the generator specification is declared. A frozen executable
  implementation, randomization binding, actual sample artifact and capture digests
  are pending; these are explicit materialization gaps, not fake file references.
- Meaning: named observed-variable identities and scalar value domains; three
  variables and 1,000 intended rows are different quantities.
- Origin/relationships: derived from the declared source; any later samples share
  that source. Independence is supported only to the extent established by the
  generator, sampling procedure and relevant assumptions.
- History: first planned definition, with current authoring provenance. No invented
  generation time or prior revision.
- Extent/exposure: the planned evidence scope is explicit. No samples are claimed
  captured or unseen; this is a public development example.

### Collection and membership

The collection definition describes its intended selection scope and purpose.
Its intended selection slot references this planned situation and the selection
rule. It is not presented as a frozen release of captured, ready-to-score cases.
Once materialization is established, the realized collection binds exact case
revisions and evidence snapshots. A generator/source case and its realized data
cases retain separate roles and derivation links. A new draw does not overwrite
an older realized case. Exact planned-slot/materialized-case wire mechanics remain
for the later lifecycle/serialization pass.

Selection provenance states this is a deliberately constructed design example,
not a random sample of all causal mechanisms. Scientific repeat slots belong to
the experiment; they do not need duplicate collection entries. In a larger
collection, every intended slot and realized membership retains its relationship.

### Task/reference handoff and readiness

The task specifies discovery scope over A/B/C and an eligible native response
contract. Different native output families need suitable task bindings rather
than forced graph conversion. The source DAG is evaluator-side evidence under
the generating assumptions; execution receives only the declared allowed inputs.
The name contrast fixes sample values, row selection and variable correspondence,
while specifying every renamed channel and other exposed context.

An exact generating DAG does not guarantee every orientation is identifiable
from the observational information supplied. Evaluation must separate structural
recovery targets, orientation/identifiability scope and knowledge assumptions.
Partial/equivalence-class outputs are not completed arbitrarily to make an exact
DAG comparison. The evaluation procedure and any derived reference view must be
declared and supported before scoring.

Current design status: the planned definition can be preserved; materialized-input
and scientific-run readiness are not established. No execution/completion or
observed name effect is asserted. If later materialization passes, comparisons
still need fixed task/reference, contrast, draw, missingness and analysis rules.

## 2. Example B: a historical CSV and graph

Situation: a hypothetical old CSV and an adjacency file are recovered. Their
filenames suggest a connection, but the original task, selection plan, variable
order mapping, producer configuration and completion evidence are absent.

### Complete preservation account

- Identity/revision: new importer-owned preservation identities, retaining source
  names as scoped aliases. No original case or run identity is manufactured.
- Boundary: exactly the recovered artifacts and examined metadata. The original
  population and any unseen siblings remain unresolved.
- Evidence bindings: on actual capture, S1 snapshots would bind bytes, locations,
  selectors and digests. This walkthrough supplies no actual files or hashes.
- Meaning: parsed shape/labels can be recorded to their established scope; the
  graph-to-variable mapping remains unresolved until evidenced. Equal dimensions
  and similar filenames do not establish alignment.
- Origin/relationships: an association candidate with its filename-based basis;
  no established identity, independence or common-cohort pairing claim.
- History: known current import event and unknown original event time/author.
- Extent/exposure: complete enumeration only of the bounded recovered set, if
  actually checked; historical completeness and past exposure remain unknown.

### Collection and membership

A reconstruction release identifies the recovered set and its current purpose.
Membership refers to the preserved candidate situation and explicitly unresolved
original association. Inclusion is justified by the current recovery procedure;
it is not evidence of the original author's selection rationale or random sampling.
If more artifacts or mappings are found, add observations and appropriate new
definitions/releases, retaining the earlier evidence and gaps.

### Task/reference handoff and readiness

The original requested output and completion policy remain unknown. A graph file
does not establish that the original pipeline completed. If a variable mapping and
suitable reference later become established, a new, explicitly retrospective
evaluation may score that surviving graph at its justified scope without knowing
the original request. It still cannot claim original task fulfillment, prospective
registration or representative cohort performance without the relevant evidence.

If competing source documents provide different reference graphs, preserve both
with their provenance, scope and uncertainty. A consensus disagreement remains
agreement against a contested reference; do not label it exact accuracy or choose
whichever reference flatters the recovered output. A reconciliation/amendment is
a separately justified versioned interpretation.

Current status: faithful preservation can succeed. Matched graph evaluation is
blocked by the missing mapping/reference in this example; population and original
fulfillment claims remain unresolved even if those particular gaps are later closed.

## 3. Example C: an interactive source with imperfect replay

Scientific purpose: identify direct parents of target Z among a declared observed
domain by permitted interventions during one source episode. The illustrative
budget is at most 20 action rounds and 100 observations per round. These are
design quantities, not authorization, executed actions or a statistical power claim.

### Complete account of the source case

- Identity/revision: local definition of the identified source/interface revision
  and intended episode; actual native episode identity is separately bound when
  evidenced.
- Boundary: declared observed domain, episode/state constraints, allowed operation
  contract and stop window. There is no fictitious pre-existing sample matrix.
- Evidence bindings: source declaration and policy refs; actual actions, responses,
  timestamps, sample identities and output artifacts are later S1/S3 observations.
- Meaning: intervention targets, values, response schema and variable identities
  must be defined. Target-specific parent claims differ from ancestry, association
  and Markov-blanket membership.
- Origin/relationships: shared simulator/source/episode links, action history and
  checkpoint/reset evidence where established; fresh independent episodes cannot
  be inferred from request IDs.
- History: definition revisions remain distinct from actual state transitions and
  new attempts. No restoration or native continuation is claimed without evidence.
- Extent/exposure: record permitted access, actual observed/captured interaction
  scope and evidence gaps. An inaccessible internal state is not an empty state.

### Collection and membership

A collection may enumerate source/episode specifications or bind an advance
selection rule for later episodes. The realized episode membership is recorded
separately. A committed rule is not a before-the-fact enumeration of realized
samples. Restricted identities/commitments follow the adopted access policy and
are not disclosed merely for public traceability.

### Task/reference handoff and readiness

The task binds Z, the meaning of direct parent, eligible response/abstention scope,
permitted actions, budget and completion rule. S2 defines these; S3 enforces the
authorized operational policy; S1 records delivery and action-response evidence.
No future experiment is authorized by this example.

A hidden structural reference, if available to an authorized evaluator, must match
the relevant source/state/episode and identify its assumptions and coverage.
If source stability during the episode is unestablished, one static reference
cannot silently judge every response. If the evaluator lacks a suitable reference,
it may still examine established action-budget compliance or output reproducibility
at their declared scope; it cannot report parent-recovery accuracy.

Exact replay is unresolved when internal state cannot be restored. A replay of a
captured transcript can check pipeline behavior under that transcript but is not
a fresh interactive episode or proof that a different policy would receive the
same responses. Equal budgets do not imply identical observations for adaptive
policies; the comparison's estimand and episode/dependence design must say what
is intended to be comparable.

Current status: the case/protocol definition is preservable. Native readiness
requires bound source and action semantics/authority. Accuracy readiness additionally
requires valid episode/reference applicability. Every status is scoped, not a single
all-good flag.

## 4. Obligations exercised and gaps exposed

| Obligation | Prospective example A | Historical example B | Interactive example C |
|---|---|---|---|
| C1-C2 identity/boundary | Planned situation versus actual realization | Current preservation versus unresolved original identity | Source/episode versus actual native state |
| C3-C4 evidence/meaning | Pending materialization and explicit variable domain | Captured evidence versus unresolved graph mapping | Access contract and later action/response schemas |
| C5-C7 lineage/history/extent | Shared generator, first definition and public development role | Candidate associations, original-time gaps and bounded recovery | Episode/reset history, inaccessible state and bounded capture |
| R1-R3 release/scope/members | Planned slots versus realized member release | Reconstructed set with explicit completeness limits | Source specs/selection rule versus realized episode membership |
| R4-R6 selection/order/history/access | Constructed example, explicit roles and later freeze | Known current recovery rule, unknown original selection | Rule timing, episode multiplicity and restricted references |
| M1-M5 exact member/role/basis | Bind actual revisions after materialization; no invented draw independence | Retain unresolved association and reconstruction basis | Bind actual episodes and reuse without inventing fresh state |

The walkthroughs expose five requirements to carry forward:

1. Planned slots, source recipes and materialized evidence need distinct states
   and identities/relations; no placeholder is counted as an observed dataset.
2. A task can be fulfilled while scientifically wrong, and a surviving output can
   be retrospectively evaluated while original fulfillment remains unknown.
3. A reference needs claim meaning, domain alignment, coverage and applicability;
   a truth-tier label by itself is insufficient.
4. Interactive comparisons must distinguish equal action/resource rules from
   equal realized inputs and fresh episodes from transcript replay.
5. Reference corrections, evaluator-only transformations and missingness cannot
   silently change original case identities, selection or allowed system information.

No gap above is claimed implemented or closed by these prose examples. They are
requirements for the design, later complete specimens and eventual validation gates.
